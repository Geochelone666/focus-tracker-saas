# Focus 2 后续交付规划

制定日期：2026-11-06。依据：原始[总规划书](focus2-roadmap.md)、当前代码与
[实际完成情况](f2-roadmap-status.md)。本文件是用户授权补充的后续规划，不改写
原始附件，也不把实现、合并、上线和真实验收混为一谈。

## 交付顺序与当前阻塞

先结束 Phase 0/1 的数据安全与集成工作，再完成 Phase 2 的执行恢复闭环。
Phase 3 的评估工具可以先做，但个性化默认策略必须等真实试点证明有效。
Google Calendar 从只读开始；Outlook、双向同步和更多任务来源由实际需求决定。
高级求解器、多人协作、收费体系和原生商店发行不作为本轮公开试用的先决条件。

当前环境可以运行本地构建、完整测试、真实 PostgreSQL 竞争测试和 fixture 浏览器
测试，也可以推送分支。GitHub API 返回 Forbidden，Supabase/Vercel 工具及真实
测试登录绑定不可用。因此远程 CI、迁移核对、真实双用户认证和部署验收仍是独立
待办。用户已授权通过 GitHub 检查后合并；无需重复征求该授权。

## Phase 6A：可以放心邀请用户试用

1. **首次使用路径。** 检查账户时区，创建首个带预计时长的任务，选择工作时段，
   预览并确认，再启动和结束专注。引导可跳过、可再次打开，不强迫授权通知或
   接入 AI。空状态直接引导用户完成下一步，错误保留已填内容。
2. **统一移动端与无障碍。** 优先日视图和明确的日期切换；安排、改时长、恢复、
   撤销均提供非拖拽操作。检查 390px、放大字体、键盘焦点、读屏状态提示，以及
   iOS Safari/Android Chrome 实际设备。浏览器自动化截图不代替设备验收。
3. **可恢复的错误处理。** 明确区分离线、登录过期、版本冲突和保存结果未知。
   不离线排队提交可能覆盖新版本的修改；结果未知沿用请求 ID 查验。错误日志
   记录请求关联信息，不记录任务正文、专注备注、OAuth token 或服务密钥。
4. **完整数据导出。** 保留现有专注 CSV，增加按账户导出的结构化数据包：任务、
   项目、目标、专注与休息记录、反思、偏好和必要的关联 ID。采用分页/有界读取，
   附带格式版本和时区说明。排除访问密钥、推送端点和外部 token；CSV 防公式注入。
   并发编辑时明确导出快照语义，不假称跨页数据是原子快照。
5. **账号删除与隐私控制。** 先列明删除范围及备份保留限制，再实现重新认证、
   用户明确确认、可重试的账户删除流程。撤销访问密钥、推送设备与外部授权，
   验证孤立记录和定时任务不会继续处理已删除账户。测试仅删除专用测试账户；
   开发授权不等于删除任何现有用户数据的授权。对第三方或备份删除延迟如实说明。
6. **上线与恢复手册。** 维护 schema/应用版本对应表、迁移前检查、逐项开关和
   保留历史数据的回退步骤。完成一次测试环境故障恢复演练；未演练的备份不能
   当成已验证恢复能力。监控认证失败、写入失败、排程冲突、通知积压及请求耗时。

Phase 6A 验收：一个全新测试用户能完成 Capture → Plan → Focus → Review → Adapt；
另一个用户无法读取或修改其数据；手机端可完成同一流程；可成功导出、撤销授权并
删除专用测试账户；发布与恢复步骤有可重复证据。

## Phase 6B：小范围真实试点

邀请明确同意的用户试用，记录真实操作问题、排程接受与修改情况、估时偏差、
错误率和移动端障碍。默认不采集任务文本到分析服务，不将私密日历发送给 AI。
先建立基线，再约定试点评估窗口和足够样本标准，避免事后挑选有利指标。

最少需要评估：从创建任务到首次专注的完成情况、计划与实际差异、重排次数、
撤销成功率及关键流程失败率。相关性只作为建议依据；不推断用户能力或健康状况。
可以对建议说“不”，不引入惩罚式连续打卡或无证据的“效率评分”。

Phase 6B 验收：修复试点中的阻断问题；至少一项可重复改善且没有降低硬约束
安全性；有明确的未解决问题清单和回退方案。数据不足则延长观察，不伪造结论。

## Phase 6C：稳定公开发行及按需商业化

公开发行前补齐隐私说明、数据保留与支持渠道，明确外部集成的失败和撤销行为。
用实测负载确定分页、聚合、索引及限流需求，保留 Next.js/Supabase/Vercel 架构，
没有性能证据不增加微服务或消息队列。

商业化先核算真实基础设施成本和支持负担，再决定是否需要付费能力。核心数据
导出、账户删除与安全控制不因套餐被取消。计费、税务、退款、支付供应商配置及
商店发行属于单独的产品决策与发布工作，不能通过开发一个按钮宣称完成。

Outlook、Todoist/Notion、双向写回、原生应用、复杂依赖或多周优化依真实需求排序。
若没有明确受益用户、可衡量收益和可靠回退路径，维持为候选项。
