# Planned versus actual — batch 4

Apply `20261025030000_planned_actual.sql` last. Branch `feat/planned-actual-v1` is stacked on the time-blocking branch. No production credentials, service grants or deployment configuration are changed.

Effective intervals are recorded atomically by a narrowly scoped SECURITY DEFINER trigger on the already owner-protected focus table. Users can read their own intervals through RLS but cannot insert/update them. Pause closes an interval; resume opens one; completion closes it using the timing guard's exact millisecond delta. Abandoned sessions do not earn focus or break credit. The trigger has no caller-controlled SQL, no public execution grant, and a fixed empty search path.

`focus_daily` splits completed intervals at real account-local midnight boundaries, including 23/25-hour DST days and midnight offset changes. Fractions are normalized to the canonical stored completed duration, preventing double counting or loss across repeated sessions. Break seconds and focus seconds remain separate. Existing history has no recoverable pause timeline: its unrecorded residual stays on the original start date, with an explicit report notice. No speculative intervals or completion dates are backfilled. Project identity on new sessions is the snapshot from focus start; old project assignment could only be inferred at the preceding migration.

Review provides 7-day, 30-day and custom 1–366-day windows, daily planned work/focus/break/completion trends, per-project and per-skill allocations keyed by IDs, lifetime task estimates versus completed actuals, overdue and deferral counts, and estimate fit. Task rows paginate 50 at a time; summaries are database aggregates rather than downloaded raw history. Today and day/week calendars show daily totals. Dashboard, projects and skills use database totals as well. Inbox/calendar/task cards show measured actuals when available.

A missing estimate or actual is displayed as missing, not a manufactured zero. A task with multiple completed focus sessions sums them once. Estimate fit is the sum of the smaller planned/measured values divided by the sum of the larger values for completed tasks with both values; for a single 60m/90m task it is 66.7%, with +30m variance. Task actuals span the task's lifetime; daily charts are restricted to the selected window. Planning counts reflect the current scheduled tasks, not a historical snapshot of past calendar edits. Deferral counts describe selected tasks ever postponed, not an invented dated event history. Completion trends use known completion timestamps; unknown legacy timestamps remain unknown.

CSV keeps its first five columns and appends break seconds, phase and task/project/skill IDs. Durations use effective focus rather than wall time. Notes retain CSV formula escaping. History remains paginated.

Validation includes actual trigger interval recording, owner isolation, inability to forge intervals, same-name project separation, 60m/90m variance, multiple intervals, cross-day/month and DST boundaries, migration ordering and previous SQL suites.
