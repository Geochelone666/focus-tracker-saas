# Time blocking and task revisions — batch 3

Branch `feat/time-blocking-v1` is stacked on `feat/focus-cycles-v1`. Apply `20261025020000_time_blocks.sql` after all preceding migrations before deploying. It adds an optional task `deadline` and a deferral counter; it reuses `scheduled_date`, `scheduled_time`, `estimated_minutes` and existing task/project/priority/series models for blocks.

Calendar offers day/week/month. The day/week grid has a 24-hour wall-clock axis, Inbox drag/drop, block movement and a draggable Resize handle. Choosing a task opens the same operations as a form above the grid, available on touch and keyboard. Drag/resize changes one occurrence; the form can change this and future unfinished occurrences. All edits preserve the deadline unless it is explicitly edited in the task form. Clear both planned date/time or use Move to Inbox to unschedule. Overlaps display warnings and remain permitted; adjacent endpoints are not conflicts. Overnight blocks continue into the next visible day. Unestimated or untimed tasks need scheduling through the editor before they form a timed block.

Times use the account IANA timezone. A nonexistent spring-forward wall time is rejected on insert/update. A repeated fall-back start uses the earlier instant, labelled in the grid. Durations represent elapsed minutes; block end labels and conflicts use actual instants. DST dates are labelled; the repeated hour shares a wall-clock row. The week grid scrolls horizontally within its own container on phones; the document does not need horizontal scrolling.

`mutate_schedule` is SECURITY INVOKER, owner scoped and accepts only declared task fields. It locks and checks the exact expected `updated_at`; future edits additionally check the snapshot revision of every affected unfinished occurrence before updating. Any conflict rolls back the entire edit, leaving completed records untouched. Web task edit/completion/trash/restore/move operations and legacy actions use this editor. AI/API/MCP permissions and existing edit scopes are unchanged. Existing web drafts are preserved on failed actions; automatic focus refresh stops when any form is edited.

Validation includes SQL migration order/RLS/optimistic conflict/recurrence regressions, DST gap/fold and overnight/layout unit tests, and fixture-backed Chromium capture → 14:00–15:30 arrangement → reload → drag → resize → mobile edit → Inbox. The local protocol fixture preserves microsecond revision strings; truncating them would cause false conflicts. Real Supabase/PostgREST and production deployment remain unverified.
